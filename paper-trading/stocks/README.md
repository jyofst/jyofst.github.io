# 주식 눌림목 스캐너 (일봉)

장 마감 뒤 하루에 한 번, 감시 범위 전체에서 눌림목 조건을 체크해. 결과는 오늘 조건을 충족한 종목, 보유종목의 현재 위치, 지난 1년 백테스트를 한 장의 보고서(`report.md`)로 정리해. GitHub Actions(`.github/workflows/stocks.yml`)가 평일 16:07 KST에 돌리고, 결과는 `stocks-data` 브랜치에 커밋해.

관찰 기록이고 매수·매도 추천이 아니야.

## 범위와 데이터

| 대상 | 데이터 | 조건 |
|---|---|---|
| 코스피 시총 상위 200 + 코스닥 시총 상위 150 (보통주만) | 공공데이터포털 금융위원회 주식시세정보 API | `DATA_GO_KR_KEY`가 있어야 해 |
| 보유종목 중 국내 종목 | 키가 있으면 위 API, 없으면 Yahoo Finance | 항상 |
| 보유종목 중 해외 종목 (SNDK, BE) | Yahoo Finance | 항상 |

- 지수 공식 구성종목은 KRX가 로그인 뒤에만 공개해. 그래서 시가총액 순위로 코스피200·코스닥150을 근사해. 우선주(코드 끝자리가 0이 아닌 종목)와 스팩은 빼.
- 공공데이터포털 시세는 다음 영업일 오후 1시쯤 올라와. 그래서 국내 종목은 하루 전 종가 기준이야.
- 보유종목은 `holdings.json`에서 바꿀 수 있어.

### 키 등록 방법

1. [공공데이터포털](https://www.data.go.kr)에서 "금융위원회_주식시세정보"를 검색해서 활용 신청을 해. 무료이고 보통 바로 승인돼.
2. 마이페이지에서 일반 인증키(Decoding)를 복사해.
3. GitHub 저장소의 Settings → Secrets and variables → Actions → New repository secret에서 이름을 `DATA_GO_KR_KEY`로 해서 넣어.

## 조건 (`rules.json`)

| 체크 | 기본값 | 뜻 |
|---|---|---|
| (기간) | `minBars` 80 | 일봉이 80개 이상 있어야 판단해 |
| 추세 | `ma60SlopeDays` 10 | 20일선 > 60일선이고, 60일선이 10일 전보다 높고, 종가가 60일선 위에 있어야 해 |
| 20일선 근처 | `nearMa20Low` 97 ~ `nearMa20High` 103 | 종가가 20일선의 97~103% 안에 있어야 해 (20일 이격도) |
| 고점 대비 조정 | `highLookbackDays` 20, `pullbackFromHighPct` 5 | 최근 20일 고점보다 5% 이상 빠져 있어야 해 |
| 거래량 감소 | `volumeDryUpRatio` 1.0 | 최근 5일 평균 거래량이 20일 평균 이하여야 해 |
| 거래대금 | `minAvgTradingValue` | 20일 평균 거래대금이 10억원(해외는 $1,000만) 이상이어야 해 |

보고서의 '정배열'(5일선 > 20일선 > 60일선)은 참고용으로만 보여줘. 판정에는 안 써. 눌림목에서는 5일선이 20일선 아래로 잠깐 내려가는 게 보통이라서야.

## 백테스트 (`backtest.json`)

신호 다음 날 시가에 사고, 종가 기준으로 손절 -5%, 익절 +10%, 최대 10거래일 보유 중 먼저 걸리는 걸로 팔아. 비용은 매수 0.1%, 매도 0.35%(수수료 + 거래세 + 슬리피지 가정)로 잡았어. 비교 기준으로는 같은 종목에서 아무 날이나 똑같이 샀을 때의 결과를 같이 보여줘.

### 분할·합병 처리

공공데이터포털 시세는 액면분할이나 합병이 보정되지 않은 원래 가격이야. 그래서 분할한 날이 가짜 폭락으로 잡혀. 실제로 LS ELECTRIC은 거래 하나가 -76%로 찍혔어. 국내 종목은 하루 가격제한폭이 ±30%니까, 종가가 하루에 30% 넘게 바뀐 날은 이런 이벤트로 보고 그 앞뒤 데이터를 끊어서 따로 계산해. 그래서 분할 직후에는 이동평균을 계산할 데이터가 모자라서 한동안 판정이 안 나와.

### 규칙 비교 실험 (`experiments.json`)

같은 데이터에 규칙을 조금씩 바꿔서 백테스트하고, 결과를 보고서에 표로 나란히 보여줘.

| 실험 | 바꾸는 것 |
|---|---|
| 정배열 종목만 | `requireAligned`: 5일선 > 20일선 > 60일선인 종목만 |
| 반등 양봉 확인 후 | `requireBounce`: 당일 양봉이면서 전날보다 오른 날만 |
| 거래량 감소 조건 제외 | `volumeDryUpRatio`를 99로 바꿔서 이 조건을 사실상 끔 |

실험은 `experiments.json`에 이름과 바꿀 값을 적으면 추가돼.

범위를 오늘 시가총액 순위로 고르기 때문에 생존 편향이 있어. 그래서 두 결과 모두 실제보다 좋게 나올 수 있으니, 둘의 차이를 봐.

## 계좌 시뮬레이션 (`portfolio.json`)

백테스트는 거래 하나하나의 성과만 봐. 계좌 시뮬레이션은 한 계좌로 지난 1년을 하루씩 다시 돌려 보는 거야. 처음 기획한 6단계 중 ③ 리스크에 해당해.

| 항목 | 기본값 | 뜻 |
|---|---|---|
| `startingCashKrw` | 10,000,000 | 가상 시작 자금 |
| `positionPct` | 10 | 종목 하나에 쓰는 돈 (그날 계좌 평가액 대비 %) |
| `maxPositions` | 10 | 동시에 들고 있을 수 있는 종목 수 |
| `variants` | 기본 규칙, 정배열 + 반등 양봉 | 시뮬레이션할 규칙 (`experiments.json`의 이름) |

- 장 마감 때 신호가 나오면 다음 날 시가에 사. 그날 신호가 빈 자리보다 많으면 최근 20일 거래대금이 큰 종목부터 사.
- 청산 규칙(손절·익절·최대 보유일)과 비용은 백테스트와 같아. 분할 같은 가격 단절이 생기면 직전 종가로 정리해.
- 비교 기준은 같은 종목들을 첫날 같은 금액씩 사서 끝까지 들고 있는 경우야.
- 보고서에 최종 자산, 수익률, 최대 낙폭, 평균 투자 비중, 자리가 없어서 놓친 신호 수를 보여줘. 해외 종목은 원화 환산 없이 쓸 수 없어서 빼고 계산해.

## 스윙 지표 신호 검증 (`indicator-test.mjs`)

스윙 트레이딩 지표표에 나온 지표별 매수·매도 신호를 각각 따로 검증해. EMA 20/60/120, 고정 VWAP, 슈퍼트렌드, 볼린저밴드, 거래량+MFI/OBV, MACD, RSI, DMI+ADX, 그리고 이걸 묶은 종합 신호까지 다 봐. 지표 계산은 `indicators.mjs`에 있어.

- 매수 신호가 나오면 다음 날 시가에 사고, 그 지표의 매도·손절 신호가 나온 날 종가에 팔아. 최대 30거래일까지 보유해. 비용은 백테스트와 같게 잡았어.
- 각 거래 수익률에서 같은 기간 전체 종목 평균 수익률을 빼서, 지표가 시장보다 얼마나 더 벌었는지(시장 대비)를 봐.
- 검증 기간을 앞 절반과 뒤 절반으로 나눠서, 두 구간 모두 같은 방향으로 나오는지도 보여줘.
- EMA120을 계산하려면 120일치 데이터가 먼저 필요해. 그래서 1년 데이터 중 뒤쪽 약 6개월만 검증 구간이 돼.
- 4시간봉 데이터가 없어서 일봉으로만 검증해.
- "안착", "지지" 같은 표현은 코드에서 구체적인 조건으로 바꿔서 썼어. 어떻게 바꿨는지는 보고서에 그대로 적혀 있어.
- 고정 VWAP의 기준점은 최근 60일 최저점으로 잡았어.

## 실행

```bash
DATA_GO_KR_KEY=... node collect.mjs   # 키가 없으면 보유종목만 받아
node backtest.mjs
node portfolio.mjs                    # results/portfolio-result.json
node indicator-test.mjs               # results/indicator-test.json
node scan.mjs                         # results/report.md
node --test stocks.test.mjs
```
